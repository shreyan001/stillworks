# DECISION_PROTOCOL

## Classify every choice
| Type | Test | Handling |
|---|---|---|
| Reversible | Cheap to undo; no money, keys, public claims, or locked design | Lead may proceed; log it; tell shreyan in the next summary |
| Consequential | Hard to undo; affects money, user funds, trust claims, prize eligibility, public statements, contracts, scope | **Must go to shreyan.** No proceeding until he answers |
If unsure → treat as consequential.

## How to raise one (one question per message)
```
Decision: <short name>
Why now: what is blocked
Evidence: facts with source + date; what is unknown
Options:
  A — tradeoff / consequence
  B — tradeoff / consequence
  (C — do nothing / defer — consequence)
Recommendation: <option> because … (labelled as recommendation)
Question: <one yes/no or pick-one question>
```

## Recording
Append to `DECISION_LOG.md` (create when first needed):
`ID · date time IST · decision · chosen option · decided by (shreyan) · evidence links · reversible?`

## Rules
- **No invented approvals.** Silence, "sounds good" about something else, or an earlier proposal is not approval.
- No invented numbers. If a parameter is needed, show how it could be set and ask.
- A user's proposed value stays labelled "shreyan's proposal" until he locks it.
- A decision can be reopened only by shreyan, or by the lead with new evidence (raise it again with this format).
